# Infra 实验环境与依赖维护

本文是 `infra-experiments` 的环境维护手册。目标不是把所有 Python 包装进一个环境，而是让训练、低精度和 serving 实验在依赖冲突时仍能独立重建、验证和比较。

## 1. 服务器基线

当前 DSW 机器已观察到：

```text
GPU: NVIDIA A100-SXM4-80GB
Driver: 570.133.20
nvidia-smi reported CUDA: 12.8
```

`nvidia-smi` 的 CUDA 版本表示驱动支持的 CUDA API 上限，不等于系统一定安装了完整 CUDA Toolkit。PyTorch 的 CUDA 构建、驱动和 GPU 可见性必须分别记录。

启动任何 CUDA 实验前，先检查：

```bash
hostname
whoami
df -hT "$HOME" /mnt/cpfs /mnt/data
nvidia-smi --query-gpu=index,uuid,name,memory.total,memory.used,utilization.gpu --format=csv,noheader
nvidia-smi --query-compute-apps=gpu_uuid,pid,process_name,used_memory --format=csv,noheader
```

如果机器由 EPIC 租约管理，必须使用当前租约的 GPU UUID，并让 `CUDA_VISIBLE_DEVICES` 与 `EPIC_GPU_UUIDS` 完全相同、顺序相同。不要把物理 GPU 编号直接写成 `0` 或 `0,1`，也不要复用过期 UUID。

## 2. 四个环境的职责

| Conda 环境 | 负责内容 | 主要依赖 | 何时使用 |
|---|---|---|---|
| `infra-core` | Phase 0、PyTorch Distributed、DDP/FSDP、TP/PP toy、基础 profiling | PyTorch CUDA、pytest、ruff、numpy、scipy、pandas、pyyaml、psutil、matplotlib | 现在建立，作为共同 reference |
| `infra-training` | ms-swift、DeepSpeed、Megatron、Transformer Engine、FP8/FP4 相关实验 | PyTorch CUDA、transformers、datasets、accelerate、deepspeed、transformer-engine、ms-swift | 进入 Phase 2/3 时建立 |
| `infra-vllm` | vLLM server、scheduler、KV cache、serving benchmark | PyTorch CUDA、vLLM 及其依赖 | 进入 Phase 4/5 时建立 |
| `infra-sglang` | SGLang runtime、Radix/prefix cache、P/D serving | PyTorch CUDA、SGLang 及其依赖 | 进入 Phase 4/5 时建立 |

分环境的原因：vLLM、SGLang、DeepSpeed、Megatron 和 Transformer Engine 可能对 PyTorch、Triton、CUDA extension 和 attention backend 有不同约束。一个环境能“安装成功”不代表其中的性能比较仍然公平。

## 3. 目录与持久化位置

建议：

```text
~/workspace/infra-experiments       Git checkout
~/storage/cache                     模型和编译缓存
~/storage/models                    模型权重
~/storage/datasets                  数据集
~/storage/checkpoints               checkpoint
~/storage/runs                      长期保留的实验结果
/tmp                                临时文件，可被清理
```

不要把模型权重、数据集、checkpoint 或大量 profiler 结果提交进 Git。实验 runner 的 `ARTIFACT_ROOT` 应指向持久化存储：

```bash
export ARTIFACT_ROOT="$HOME/storage/runs/infra-experiments"
```

## 4. 创建共同环境 `infra-core`

先确认 Conda 和当前 Python：

```bash
conda --version
which conda
```

创建环境：

```bash
conda create -n infra-core python=3.11 -y
conda activate infra-core
```

先安装 PyTorch。PyTorch 官方 Linux 安装页会根据操作系统、Python 和 CUDA 版本生成当前命令；不要从旧博客复制版本。对于当前驱动支持 CUDA 12.8 的机器，优先选择官方 CUDA 12.8 构建：

```bash
python -m pip install --upgrade pip
python -m pip install torch torchvision torchaudio \
  --index-url https://download.pytorch.org/whl/cu128
```

然后安装共同工具和本仓库：

```bash
conda install -y numpy scipy pandas pyyaml matplotlib seaborn psutil packaging ipykernel
python -m pip install -e '.[dev]'
```

这里的 `pyproject.toml` 保持 PyTorch 未固定，是有意设计：不同服务器的 CUDA runtime、驱动和 GPU 架构可能不同。实际安装版本必须进入每次 run 的 `environment.json`。

## 5. 创建训练环境 `infra-training`

不要在 `infra-core` 中追加训练栈。进入 Phase 2/3 时，从干净环境开始：

```bash
conda create -n infra-training python=3.11 -y
conda activate infra-training
python -m pip install --upgrade pip
python -m pip install torch torchvision torchaudio \
  --index-url https://download.pytorch.org/whl/cu128
conda install -y numpy scipy pandas pyyaml psutil packaging
python -m pip install transformers datasets accelerate deepspeed
```

`transformer-engine`、`ms-swift` 和 Megatron 相关包应在对应 Phase 开始时，根据它们当时的官方兼容矩阵和 commit 安装。安装前记录：

```text
PyTorch version
CUDA runtime
GPU model/compute capability
Transformer Engine version
DeepSpeed version
Megatron Core version
ms-swift version/commit
```

A100 可用于 BF16、DDP/FSDP 和许多基础训练实验；不能把 A100 上的结果直接写成 Hopper/Blackwell 原生 FP8/FP4 性能结论。

## 6. 创建 serving 环境

### vLLM

```bash
conda create -n infra-vllm python=3.11 -y
conda activate infra-vllm
python -m pip install --upgrade pip
python -m pip install torch torchvision torchaudio \
  --index-url https://download.pytorch.org/whl/cu128
python -m pip install vllm
```

### SGLang

```bash
conda create -n infra-sglang python=3.11 -y
conda activate infra-sglang
python -m pip install --upgrade pip
python -m pip install torch torchvision torchaudio \
  --index-url https://download.pytorch.org/whl/cu128
python -m pip install sglang
```

vLLM 与 SGLang 必须分别记录版本、commit、attention backend、Triton 版本和启动参数。L05/L06 的公平比较要求同一模型、同一请求 manifest、同一 dtype、同一采样配置和同一 GPU 约束，但不要求两个框架共享 Python 环境。

## 7. 统一验证协议

每个环境激活后都执行以下检查。始终使用 `python -m pip`、`python -m pytest`，避免调用到环境外的可执行文件：

```bash
which python
python -V
python -m pip -V
python - <<'PY'
import torch
print("torch:", torch.__version__)
print("torch CUDA runtime:", torch.version.cuda)
print("CUDA available:", torch.cuda.is_available())
print("device count:", torch.cuda.device_count())
for i in range(torch.cuda.device_count()):
    print(i, torch.cuda.get_device_name(i))
PY
```

`infra-core` 还要执行：

```bash
python -m pytest -q
python -m ruff check .
```

serving 环境还要记录：

```bash
python -m pip show vllm 2>/dev/null || true
python -m pip show sglang 2>/dev/null || true
```

系统 profiling 工具不由 Conda 负责，单独检查：

```bash
command -v nsys || true
command -v ncu || true
command -v nvcc || true
```

## 8. 实验启动顺序

```text
激活目标 Conda 环境
  -> which python / python -m pip -V
  -> nvidia-smi 与 GPU UUID/租约检查
  -> git status、commit、运行中的进程检查
  -> correctness smoke
  -> 普通 benchmark
  -> profiler/Nsight
  -> 审查 environment.json、metrics、原始日志和失败原因
```

Phase 0 当前 runner：

```bash
conda activate infra-core
cd ~/workspace/infra-experiments
export ARTIFACT_ROOT="$HOME/storage/runs/infra-experiments"

./scripts/run_phase0.sh cuda day1-cuda-smoke
./scripts/run_phase0.sh cuda day1-cuda-profile --profile
```

runner 会拒绝覆盖已有 run directory。每次使用新的 run id；不要通过删除旧目录来“重跑同名结果”。

## 9. 升级与故障排查

### `ModuleNotFoundError: torch`

```bash
which python
python -m pip -V
python -c "import torch; print(torch.__file__)"
```

如果 `python` 和 `pip` 不在同一个 Conda 环境，先重新执行 `conda activate <env>`。不要用裸 `pytest`，使用 `python -m pytest -q`。

### `torch.cuda.is_available()` 为 `False`

依次检查：

1. `nvidia-smi` 是否能看到 GPU；
2. 当前 PyTorch 是否为 CUDA 构建，而非 CPU build；
3. driver 是否满足该 PyTorch CUDA 构建；
4. `CUDA_VISIBLE_DEVICES` 是否为空、过期或指向错误 UUID；
5. 是否有容器/租约层面的 GPU 隔离。

### 安装新包后出现 extension 或 Triton 冲突

不要在原环境中连续试装多个版本。记录现有环境，创建新的 Conda 环境，重新安装最小依赖，再做 correctness smoke。原环境保留用于复现旧结果。

### PyTorch/CUDA 版本升级

升级前必须保存：

```bash
conda env export --no-builds > "${CONDA_DEFAULT_ENV}.before-upgrade.yml"
python -m pip freeze > "${CONDA_DEFAULT_ENV}.before-upgrade.freeze.txt"
```

升级后重新跑同一个固定 workload，并将结果标记为新的环境条件；不要把新旧环境的性能数字放进同一张正式比较表而不加环境分组。

## 10. 维护规则

- 环境名表达职责，不表达某次实验的日期。
- 版本、commit、CUDA runtime 和 GPU UUID 以 `environment.json` 为事实来源。
- 不在 README 或脚本中写死个人路径、服务器 hostname、密码或租约 UUID。
- 不把模型、数据、checkpoint、trace 和大型结果加入 Git。
- 修改依赖后先跑最小 correctness，再跑 benchmark；失败运行也保留。
- Microbenchmark、component 和 end-to-end 结果分开记录。
- 环境能运行不等于实验科学有效；还必须检查 workload 合同、原始日志、正确性和证据边界。
